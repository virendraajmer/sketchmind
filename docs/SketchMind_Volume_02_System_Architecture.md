# Purpose

This document defines the high-level architecture of SketchMind.

The objective is to help AI coding agents understand the system boundaries, responsibilities, execution pipeline and implementation strategy before writing code.

---

# Problem

Traditional drawing systems work with pixels and geometry.

SketchMind works with **meaning first**.

The architecture separates educational reasoning from graphical rendering.

---

# Design Goals

- AI reasons about concepts, not graphics.
- Drawing must be deterministic.
- Support unlimited diagram types.
- Renderer independent.
- Extensible through plugins.
- Every component has one responsibility.

# Component Responsibilities

## AI Drawing Agent

- Understand user request
- Determine diagram type
- Invoke Visual Planning Agent

Never generates drawing commands.

---

## Visual Planning Agent

Creates a visual plan.

Example:

Input:
"Draw a movable pulley"

Output:
- Fixed pulley
- Movable pulley
- Rope
- Load
- Ceiling
- Force direction

---

## Diagram Reasoning Agent

Produces semantic relationships.

Example:

- Rope wraps pulley
- Load attached to movable pulley
- Pulley attached to ceiling

Output is a Diagram AST.

---

## Diagram AST

The canonical representation of a diagram.

Contains:

- Objects
- Relationships
- Labels
- Metadata
- Anchors
- Properties

Contains no geometry.

---

## Constraint Engine

Transforms relationships into layout constraints.

Examples:

- Above
- Below
- Inside
- ConnectedTo
- CenteredOn
- WrapAround
- ParallelTo

---

## Layout Engine

Computes positions and dimensions.

Produces a Layout Model.

No drawing occurs here.

---

## Stroke Planner

Converts layout into natural drawing order.

Example:

1. Ceiling
2. Pulley
3. Rope
4. Load
5. Labels
6. Arrows

Produces a Stroke AST.

---

## Stroke Runtime

Executes strokes.

Supports:

- Play
- Pause
- Resume
- Speed
- Undo
- Replay

---

## Renderer Adapter

Responsible only for rendering.

Examples:

- Konva
- SVG
- Canvas
- PDF
- WebGL

No educational logic.

# Internal Models

The system uses four independent models.

Diagram AST
- Semantic

Constraint Model
- Relationships

Layout Model
- Geometry

Stroke AST
- Drawing sequence

Never combine these models.

---

# AI Boundaries

AI is responsible for:

- Understanding
- Reasoning
- Planning

Software is responsible for:

- Layout
- Geometry
- Rendering
- Animation

---

# Extensibility

Support:

- Multiple AI providers
- Multiple renderers
- Third-party primitives
- Domain plugins
- Future simulation engines

---

# Constraints

- No renderer-specific logic in AI.
- No coordinates generated by AI.
- No SVG generated by AI.
- No canvas commands generated by AI.

AI produces semantic structures only.

---

# Expected Behavior

Input:

Draw a hut.

System should:

1. Understand "hut".
2. Build Diagram AST.
3. Compute layout.
4. Plan strokes.
5. Animate drawing.

The same request should always produce equivalent diagrams.

# Final Principle

SketchMind is a reasoning engine with a rendering backend.

The AI understands the diagram.

The engine computes the diagram.

The renderer draws the diagram.
